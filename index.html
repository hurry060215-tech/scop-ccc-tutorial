Cell-Cell Communication Analysis

这份教程按“生物学问题 → 方法选择 → 参数理解 → 结果结构 → 图形解释”的顺序讲解 scop 中的细胞通讯功能。图谱部分优先使用 scop 自己的 CCCHeatmap()、CCCNetworkPlot()、CCCStatPlot() 生成；需要真实 CellChat 或 NicheNet 后端对象的专属图会明确标注。

一句话理解：细胞通讯分析是在问：“哪个细胞群像发信人，哪个细胞群像收信人， 中间可能通过哪一对 ligand-receptor 递信号？”它给的是候选机制，不是因果证明。

分析逻辑

1. 定义身份先决定 group.by：细胞类型、状态、空间区域，还是实验分组。
2. 选择方法LIANA 做广筛，CellChat 做通路网络，CellPhoneDB 做置换检验，NicheNet 做 ligand-target。
3. 看长表每行是一条 sender → receiver 的 L-R 候选事件。
4. 选图解释矩阵看强弱，网络看方向，统计图看排序和差异。
5. 回到验证检查基因表达、空间邻近、重复样本和文献机制。
你想回答的问题优先函数优先图解释方式
谁和谁通讯最强？RunLIANA(), RunCellChat()heatmap, circle, scatter先讲 sender、receiver 和 hub，不急着讲单个基因。
哪些 L-R 对最值得看？RunLIANA(), RunCellphoneDB()dot, bubble_lr, bar看 ligand 是否在 sender 表达，receptor 是否在 receiver 表达。
某条 pathway 如何连接细胞群？RunCellChat(), RunLIANA()pathway, pathway_bubble, lr_contribution先讲通路，再讲贡献最大的 L-R 对。
条件变化后通讯怎么变？RunCellChat(), RunMultiNichenetr()comparison, diff_heatmap, diff_network, ranknet强调实验设计和样本重复。
哪个 ligand 可能驱动 receiver 基因程序？RunNichenetr(), RunMultiNichenetr()ligand_target, gene把 ligand 活性和 receiver target genes 连起来。

方法选择

scop 函数像什么最适合结果存放
RunLIANA()多个侦探一起投票筛线索第一轮广泛筛选 L-R 候选srt@tools[["LIANA"]]
RunCellChat()把信号路网画成城市交通图通路网络、细胞角色、条件差异srt@tools[["CellChat"]]
RunCellphoneDB()经典数据库加置换检验显著 L-R 对和 CellPhoneDB 风格结果srt@tools[["CellphoneDB"]]
RunNichenetr()从 receiver 的基因变化倒推 sender ligand解释接收细胞目标基因程序srt@tools[["Nichenetr"]]
RunMultiNichenetr()带样本重复的 NicheNet多样本、多条件差异通讯srt@tools[["MultiNichenetr"]]
RunscOMM()给 query 细胞预测身份标签准备可靠 group.by，不是 L-R 推断metadata + srt@tools[["scOMM"]]

代码式讲解

这一节按真实分析顺序写：先把细胞身份定准，再选通讯后端，最后用同一套 CCC* 函数解释。 每段代码旁边都说明它回答的生物学问题。

0. 先确认 group.by：通讯分析的地基

CCC 的 sender 和 receiver 都来自 group.by。如果这个列是错误注释、过细 cluster 或有太多小群， 后面的 ligand-receptor 结果会跟着偏。

  • 生物学含义：把单个细胞归成能解释功能的群体，例如 beta cell、macrophage、ductal cell。
  • 最小检查：每个群有足够细胞，marker 表达合理，实验条件和样本 ID 没混。
关键参数怎么理解
group.by决定“谁发信、谁收信”的 metadata 列；推荐用人工校正后的细胞类型。
assay/layer决定使用哪套表达矩阵；大多数通讯方法应使用 normalized data。
sample.by多样本方法需要真实 biological sample，不要填细胞 barcode。
 
library(scop)
library(Seurat)

data("pancreas_sub", package = "scop")
srt <- pancreas_sub

stopifnot("CellType" %in% colnames(srt@meta.data))
srt$CellType <- factor(srt$CellType)
table(srt$CellType)

# 可选：确认 marker 和低维图是否支持这个注释
DimPlot(srt, group.by = "CellType", label = TRUE)

1. RunscOMM(): 先把细胞标签做稳

RunscOMM() 不是通讯推断，它是 reference-to-query 标签预测。它出现在 CCC 教程里，是因为通讯分析对细胞身份极其敏感： sender/receiver 分错，所有 L-R 边都会变。

  • 生物学问题：query 细胞最像 reference 里的哪类细胞？罕见细胞有没有被识别出来？
  • 结果用途：把预测标签写入 metadata，再作为 RunLIANA()、RunCellChat() 的 group.by。
关键参数怎么理解
reference带可信标签的参考对象，相当于“答案书”。
reference_label参考对象中的标签列，例如 CellType。
features用于分类的基因；为空时由函数自动选择。
prediction_prefix预测列名前缀，避免覆盖已有 metadata。
evaluate/truth_colquery 有真实标签时评估准确率和 rare recall。
scomm_epochs神经网络训练轮数；教学可小，正式分析可增加并检查稳定性。
 
query <- RunscOMM(
  srt = query,
  reference = reference,
  reference_assay = "RNA",
  query_assay = "RNA",
  reference_label = "CellType",
  prediction_prefix = "predicted_",
  scomm_epochs = 10
)

table(query$predicted_CellType)
query$CellType <- query$predicted_CellType

2. RunLIANA(): 第一轮广筛 L-R 候选

RunLIANA() 最适合作为入门起点。它把多个 L-R 评分思路统一到一张长表里， 适合先看“哪些细胞对”和“哪些 L-R 对”反复被支持。

  • 生物学问题：哪些细胞群之间可能存在较强信号交流？哪些 ligand-receptor 候选最稳？
  • 读图顺序：先 heatmap/circle 看细胞对，再 dot/bar 下钻到 L-R 对。
关键参数怎么理解
methodLIANA 内部参与评分的方法；natmi/connectome/logfc/sca/cellphonedb 从不同角度给候选排序。
resourceL-R 数据库资源；Consensus 是稳妥默认值。
min_cells每个细胞群最低细胞数，像“最低证据人数”。
return_all是否返回未通过筛选的候选；新手建议 FALSE。
...传给 LIANA 后端的高级参数，复现实验时再精细设置。
 
srt <- RunLIANA(
  srt,
  group.by = "CellType",
  method = c("natmi", "connectome", "logfc", "sca", "cellphonedb"),
  resource = "Consensus",
  min_cells = 5,
  return_all = FALSE
)

CCCHeatmap(srt, method = "LIANA",
  plot_type = "heatmap", display_by = "aggregation")
CCCHeatmap(srt, method = "LIANA",
  plot_type = "dot", display_by = "interaction", top_n = 30)

3. RunCellphoneDB(): 用置换检验看显著 L-R 对

RunCellphoneDB() 适合需要对齐 CellPhoneDB 文献流程的分析。它的核心思想是： 真实细胞标签下的 L-R 表达组合，是否比随机打乱标签更突出。

  • 生物学问题：某个 sender-receiver 组合里的 L-R 对是否具有统计支持？
  • 解释重点：score 看表达支持，pvalue 看置换检验显著性。
关键参数怎么理解
methodstatistical_analysis 做置换检验；analysis 更快但统计支持弱；degs_analysis 结合 DEG。
convert_to_human小鼠数据接 CellPhoneDB 时通常设 TRUE，转换到人类同源基因。
threshold某基因在细胞群内表达细胞比例的下限。
pvalue显著性阈值，越小越严格。
iterations置换次数；越大越稳但更慢。
microenvs限制哪些细胞群可互相通讯，空间/组织区域分析很有用。
cores并行核数，影响运行速度。
 
srt <- RunCellphoneDB(
  srt,
  group.by = "CellType",
  species = "Mus_musculus",
  method = "statistical_analysis",
  convert_to_human = TRUE,
  threshold = 0.1,
  pvalue = 0.05,
  iterations = 1000,
  cores = 4
)

CCCHeatmap(srt, method = "CellphoneDB",
  plot_type = "bubble_lr", display_by = "interaction",
  pairLR.use = c("Jag1-Notch1", "Wnt5a-Fzd2"))

4. RunCellChat(): 看 pathway 网络和细胞角色

RunCellChat() 更偏“通讯网络生态学”：它不仅保留 L-R 对，还会聚合到 signaling pathway， 并分析哪个细胞更像发送者、接收者或网络 hub。

  • 生物学问题：WNT、NOTCH、CXCL 等通路主要从哪里发出，流向哪里？处理组和对照组网络是否改变？
  • 读图顺序：先看 circle 总网络，再用 pathway 或 lr_contribution 解释具体通路。
关键参数怎么理解
species选择 CellChat 数据库物种：人、小鼠或斑马鱼。
split.by先按某列拆分后分别分析，适合分条件运行。
annotation_selected只保留指定细胞类型，适合聚焦某个生态位。
group_column/group_cmp条件比较设计，例如 treated vs control。
threshCellChat 通讯显著性过滤阈值。
min.cells细胞群最低细胞数，太小的群会被排除。
 
srt <- RunCellChat(
  srt,
  group.by = "CellType",
  species = "Mus_musculus",
  min.cells = 10,
  thresh = 0.05
)

CCCNetworkPlot(srt, method = "CellChat",
  plot_type = "circle", display_by = "aggregation")
CCCStatPlot(srt, method = "CellChat",
  plot_type = "lr_contribution", signaling = "NOTCH")

5. RunNichenetr(): 从 receiver 基因程序倒推 ligand

RunNichenetr() 的问题更进一步：不是只问 ligand 和 receptor 是否共表达， 而是问 sender 里的哪些 ligand 最能解释 receiver 细胞中的目标基因变化。

  • 生物学问题：某个接收细胞状态改变，可能由哪些外源 ligand 驱动？
  • 最佳图：ligand_target，把候选 ligand 和 receiver target genes 连起来。
关键参数怎么理解
receiver要解释的接收细胞群，是 NicheNet 的核心锚点。
sender候选发送细胞群；"all" 表示全部非 receiver 群。
condition.by/condition_oi/condition_reference定义 receiver 中的差异表达背景。
modeaggregate 做条件差异；custom 使用自定义目标基因集。
geneset自定义 receiver target genes，例如 DEG 或通路基因。
top_n_ligands/top_n_targets控制优先展示多少 ligand 和 target。
lr_network/ligand_target_matrix传入自定义 NicheNet 先验模型。
 
geneset_oi <- c("Ins1", "Ins2", "Gcg", "Pdx1", "Mafa")

srt <- RunNichenetr(
  srt,
  group.by = "CellType",
  receiver = "Endocrine",
  sender = "all",
  mode = "custom",
  geneset = geneset_oi,
  background_expressed_genes = rownames(srt),
  species = "Mus_musculus",
  top_n_ligands = 30,
  top_n_targets = 200
)

CCCHeatmap(srt, method = "Nichenetr",
  plot_type = "ligand_target", top_n = 30)

6. RunMultiNichenetr(): 多样本、多条件的差异通讯

RunMultiNichenetr() 是更接近真实队列研究的设计。它不是把所有细胞混在一起比较， 而是把 sample 层面的重复纳入优先级判断。

  • 生物学问题：疾病组相对对照组，哪些 sender-receiver-ligand-target 轴稳定改变？
  • 解释重点：优先相信跨样本一致、cell type 特异、receiver target genes 也支持的信号。
关键参数怎么理解
sample.by真实样本 ID，是多样本统计的核心。
condition.by实验条件列，例如 disease/control。
condition_oi/reference指定关注条件和参考条件。
receiver_celltypes重点解释哪些接收细胞类型。
sender_celltypes候选发送细胞；为空时使用可用细胞群。
batches/covariates批次和协变量，避免把技术差异误读成通讯变化。
fraction_cutoff/min_cells过滤低表达或低细胞数的 sample-celltype 组合。
 
srt <- RunMultiNichenetr(
  srt,
  group.by = "CellType",
  sample.by = "sample_id",
  condition.by = "condition",
  condition_oi = "treated",
  condition_reference = "control",
  receiver_celltypes = "Endocrine",
  sender_celltypes = c("Ductal", "Pre-endocrine"),
  species = "Mus_musculus",
  min_cells = 10,
  empirical_pval = TRUE,
  top_n_interactions = 250
)

CCCHeatmap(srt, method = "MultiNichenetr",
  plot_type = "ligand_target")
统一出口：ccc_to_liana() 用于把不同后端转成 LIANA-like 长表； ccc_to_adata() 用于和 OmicVerse communication AnnData 互通。初学者先知道它们是“格式转换器”即可。

LIANA 深入说明

RunLIANA() 需要重点理解：LIANA 不是单一算法，而是一个整合框架。 可以把它想成“通讯分析的评审委员会”：不同方法从不同角度给 L-R 对打分，最后把证据整理到一张统一表里。

为什么适合第一轮筛选？

因为单一方法容易偏向某种证据。LIANA 同时整合表达强度、细胞群特异性、rank 和数据库资源，更适合从大量候选中找稳定信号。

为什么不能只看一个分数？

有些列是 score，越大越强；有些列是 rank，越小越好；有些类似 p-value。解释时要先确认该列的语义。

srt <- RunLIANA(
  srt,
  group.by = "CellType",
  method = c("natmi", "connectome", "logfc", "sca", "cellphonedb"),
  resource = "Consensus",
  min_cells = 5,
  return_all = FALSE
)
LIANA 参数通俗解释怎么选
group.by把细胞分成“发信人/收信人”的身份列。用高置信度细胞类型；不要直接用粗糙 cluster。
method让哪些内部框架参与“投票”。探索阶段用默认组合；复现实验时写清楚方法列表。
resource使用哪套 ligand-receptor 数据库。Consensus 适合默认使用；特殊研究可指定资源。
min_cells每个细胞身份至少多少细胞才参与。像“最低证人数”。太低不稳，太高会丢小群。
return_all是否把所有可能交互都返回。新手建议 FALSE，否则结果很大且噪声多。
...传给 liana::liana_wrap() 的高级参数。只有在熟悉 LIANA 原生接口时再用。
读 LIANA 结果的顺序：先用 heatmap/circle 看细胞对，再用 dot/bar 找 L-R 对， 然后用 pathway_summary 看通路，最后回到表达图验证 ligand 和 receptor。

参数字典

这些参数在多个函数中反复出现。理解它们，比死记函数更重要。

参数像什么含义常见坑
srt整本通讯记录本Seurat 对象，包含表达矩阵和 metadata。没有 normalized data 时很多方法会不稳。
group.by给细胞贴身份牌定义 sender 和 receiver 的 metadata 列。标签错，通讯结果就跟着错。
species选择语言词典选择人、小鼠、斑马鱼等数据库或先验。物种选错会造成基因匹配失败。
assay, layer选择用哪本表达账本指定表达矩阵来源。CellPhoneDB 通常用 normalized expression。
sender.use, receiver.use只看某些发信人/收信人过滤细胞方向。名字必须和 group.by 里的水平一致。
ligand.use, receptor.use只看某些关键词过滤基因。大小写和基因符号要一致。
signaling只看某条信号公路按 pathway 过滤。不同后端 pathway 命名不完全一致。
pairLR.use指定一封信的完整地址过滤某个 L-R 对。格式可能是 Ligand-Receptor 或后端自己的名称。
thresh, pvalue可信度门槛显著性或过滤阈值。阈值越严图越干净，但可能漏掉弱信号。
top_n只展示前 N 条控制图上显示多少结果。不是分析阈值，只是绘图展示阈值。
display_by看森林还是看树aggregation 看细胞对总量，interaction 看单条 L-R。初学者先 aggregation，再 interaction。
condition.by, sample.by实验设计标签条件和样本层级。不要用细胞 ID 代替 biological sample。

推荐工作流

# 1. 第一轮筛选：LIANA
srt <- RunLIANA(srt, group.by = "CellType", resource = "Consensus", min_cells = 5)

# 2. 看整体细胞对
CCCHeatmap(srt, method = "LIANA", plot_type = "heatmap", display_by = "aggregation")
CCCNetworkPlot(srt, method = "LIANA", plot_type = "circle", display_by = "aggregation")

# 3. 下钻到 L-R 对
CCCHeatmap(srt, method = "LIANA", plot_type = "dot", display_by = "interaction", top_n = 30)
CCCStatPlot(srt, method = "LIANA", plot_type = "bar", display_by = "interaction", top_n = 20)

# 4. 如果有明确 receiver 基因程序，再跑 NicheNet
srt <- RunNichenetr(
  srt,
  group.by = "CellType",
  receiver = "Endocrine",
  sender = "all",
  mode = "custom",
  geneset = geneset_oi,
  background_expressed_genes = rownames(srt),
  species = "Mus_musculus"
)
CCCHeatmap(srt, method = "Nichenetr", plot_type = "ligand_target")
